# Extending the original 625k H/J table to J6 and J8

`ambi_aux_j68_625k.json` adds twelve settings to the original
`ambi_aux_hj_sweep_625k.json` experiment: H1/H2/H3, J6/J8, and the soft-inner /
soft-terminal and soft-inner / return-terminal arms. Existing J1/J2/J4 results
are reused; no J4 or J16 evaluations are requested.

The frozen 625k checkpoint, five full 500-decision episodes (environment seeds
101–105, controller seed 55), N128, B256, C32/A4 per round, tau .01, critic-first
update order, inherited adaptive alpha, and decision-local reset are preserved.
Both arms fit entropy-augmented interior targets. Soft terminal bootstrapping
includes outer entropy; return-only terminal bootstrapping does not.

Replay retains all rounds' data. Capacity is 3072 throughout this extension,
versus 2048 in the original table: H3/J8 needs 128*3*8 = 3072 transitions.
Sampling remains uniform with replacement from the populated buffer. Additional
unused capacity does not enter the sampling range. J6 performs 192 critic and
24 actor/alpha steps per decision; J8 performs 256 and 32 respectively.

Execution follows the original compiled mode and supported mixed GPU pool,
without the later deterministic-v1 override from the actor-budget experiment.
Use the original frozen-prior bundle. Historical J4 comparisons are pinned to
source `ea4892b48d46cfb61ecce11077505aba15bf7564`; their resolved planner identities
must differ only in J, derived totals, and full-retention capacity. Later
interleaving and round-replay options remain off. Source provenance is retained
rather than changing global identity rules. These are exploratory comparisons
with the original numerical variability, not bitwise matched runtime results.

Use `slurm/ambi_aux_hj_sweep.py prepare --baseline-kind round_budget` with the
original campaign and this matrix. Run `slurm/run_ambi_aux_hj_sweep_oscar.sbatch`
with a smoke gate at H3/J8 for both arms, then a production array of twelve
complete panels. Each panel evaluates all five seeds; no episode-shard merge
is needed. Request enough wall time for J8 (up to four hours on the supported
pool), and use live account allowance for concurrency.

Performance runs log paired improvement over the original prior. Diagnostic
runs retain per-update, per-decision and episode histories, raw trace artifacts,
probes, and `comparison/j4_gain_*` against the corresponding original J4 cell.
The CPU watcher uses four publishers for this campaign; request 8 CPUs and
64 GiB for it. Other campaigns retain the default of two publishers.
